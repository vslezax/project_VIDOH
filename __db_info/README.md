# Event Aggregator — Database Model

## Назначение
Сервис-агрегатор мероприятий. Пользователи ищут события, покупают билеты,
оставляют отзывы и добавляют в избранное. Организаторы — внешние
физлица/юрлица. Модераторы управляют контентом: событиями, ценами,
юридическими документами, организаторами.

## Границы модели
- Users — только потребители. Не управляют событиями и организаторами.
- Organizers — самостоятельные сущности (физлицо или юрлицо), не связаны с users.
- Модератор (роль `moderator` в user_roles) — единственный, кто правит
  события, цены, utc_offset, юридические документы.
- Время хранится в UTC (timestamptz), отображается по utc_offset.
  utc_offset задаётся модератором вручную, от локации не зависит.
- Один билет = одна цена. Лимиты продаж и окна продаж не поддерживаются.
- Теги, подписки, история просмотров — намеренно исключены.
- Юридические документы — дочерняя сущность события (несколько записей).

## Ключевые домены
1. Users & Auth — пользователи, роли, сессии.
2. Organizers — организаторы и их медиа.
3. Geography — countries → cities → venues.
4. Categories — иерархия категорий.
5. Media — единая библиотека файлов.
6. Events — события, сессии, связи, ссылки, юр. документы.
7. Tickets — типы билетов события с одной ценой.
8. Promo — промокоды.
9. User interactions — избранное, отзывы.
10. Orders — заказы, позиции, выпущенные билеты, платежи.

## Формат файлов
- schema.dbml — полная схема (машиночитаемо + человекочитаемо).
- diagram.mermaid — общая ER-диаграмма для визуального обзора.
- invariants.md — правила целостности и частичные уникальные индексы.
- open-questions.md — известные пробелы и план развития.
